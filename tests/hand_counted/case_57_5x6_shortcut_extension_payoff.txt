# Found by a random search specifically demonstrating the actual payoff of dead-path
# pruning: BBMSInter's shortcuts are set once and never change, even after the node
# they point at stops being relevant. BBMSDppInstant (case_58, same curve) prunes dead
# paths and *extends* the shortcuts that used to point at them further up the tree,
# so a single shortcut hop there can cover ground that BBMSInter needs to chain
# several hops through. On this curve, nca_regular_hops is identical between the two
# (36 -- confirmed below), isolating the entire difference to nca_shortcut_hops:
# BBMSInter needs more shortcut hops (98) than BBMSDppInstant needs (83) to do the
# exact same NCA queries, purely because BBMSDppInstant's shortcuts reach further per
# hop thanks to 5 dead-path pruning events extending them along the way.
#
# Cross-checked against the real binary before being written down here.

algorithm BBMSInter
p 5
1 1
2 4
4 4
4 0
0 1
q 6
0 4
2 4
4 0
1 0
0 3
5 1
expect nca_regular_hops 36
expect nca_shortcut_hops 98
expect shortcuts_written 46
